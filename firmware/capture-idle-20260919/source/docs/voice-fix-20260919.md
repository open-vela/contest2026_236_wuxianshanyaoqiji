# 烧录后 Wi-Fi 未连接与录音 -5 排查

## R2：修正上一版镜像未更新 ROMFS

再次上板发现上一版有新应用命令，但 `/etc` 仍是旧启动脚本和旧媒体配置。官方 Board.mk 只跟踪媒体目录的时间，不跟踪内部文件；rcS 预处理也未跟踪被 include 的 rcS.nsh。因此之前源码解析测试通过、镜像组件校验通过，仍未覆盖实际固件中的配置内容；上一版不能宣称已修好。

R2 在板级 Makefile 明确声明上述依赖。新增最终镜像校验：生成的完整 ROMFS 必须实际存在于 nsh.fex，三个媒体文件必须与源码一致，rcS 必须包含 qiji_config wifi_reconnect 且不能提前 ntpcstart。直接使用旧版镜像验证时应拒绝。

新通用包名 `qiji-chat-voice-fix-r2.img`。另按用户指定的默认调试网络生成 `qiji-chat-voice-fix-r2-2f-debug.img`，仅此本地镜像预置 Wi-Fi；不放入公开源码或通用归档，不预置云端 Key。私有打包脚本通过安全输入取得密码，打包后恢复官方数据目录原值。

## 实机确认

新固件已烧录后，设备保存的网络是官方 `Rivotek-Visitor`，并绑定旧 BSSID；IP 为工厂 `10.0.0.2`，时钟为 1970 年。原私有配置没有保留，阿里语音 Key 和豆包配置需要重新恢复。镜像不会嵌入密码或云端 Key。

本次已通过 `qiji_config wifi` 保存用户指定的网络，连接到 `2F`，DHCP 获得 `192.168.5.158`；ping 阿里域名成功，延迟 35–38 ms。重新保存豆包拟人模型和阿里 Key，并通过完整读取核对配置项存在。网络校时未收到样本，已临时用电脑 UTC 校准；不能将此次手动校时写成 NTP 成功。

## -5 的直接原因

实机日志：`media_policy init failed: -12` → `media daemon exit` → `media_recorder_open failed, errno=2` → `capture open failed`。录音失败返回 `-EIO`（-5）。该链路在访问 ASR 前就失败，不是阿里模型不可用。

官方 `fix_gemini_s1.sh` 替换 `graph.conf` / `criteria.txt`，没有同步替换原始 `settings.pfw`。原策略引用 MuteMode、NotifyVolume 等已不存在的 criterion，也引用与最小 graph 不一致的音量滤镜。

用官方 PFW C 解析器复现原配置失败：

```text
Criterion 'MuteMode' not found
Bad 0th config in domain 'MusicVolumeDomain'
FAIL: media policy rejected
```

新策略文件在 `app/gemini_chat_minimal/media/`，与官方最小 PCM graph 成套，录音路由 abufsink@acap、播放路由 abufsrc@apb，音量目标 VolAcap / VolApb。保留媒体策略功能，未关闭媒体服务。

## 修复

- prepare_aliyun_tts.py 安装配套 criteria/settings，并核对 graph 节点存在。
- NTP 在 Wi-Fi DHCP 完成后启动；阻止 rcS 提前启动默认 pool.ntp.org 实例，否则之后配置的阿里校时列表不会生效。
- Wi-Fi 保存前建立配置目录；关联失败时明确返回，避免继续用未连接网卡申请 DHCP。
- 录音前分别检查网络、Key 和时间，界面显示具体原因。
- 修复 test_asr：原封装启动 detached pthread 后 NSH builtin 结束会结束该线程，改为同步识别，只打印结果，不将诊断音频送进对话。
- 新增 voice_status，只显示后端、Key 是否配置、时间是否设置，不显示密钥。
- tools/restore_board_config.ps1 在格式化烧录后恢复 Wi-Fi/豆包/阿里并用电脑 UTC 校时，安全输入密码，不在项目落盘；需要 PowerShell 7。

## 验证边界

官方 PFW 解析器验证新策略、录音播放路由、音量/静音切换通过。之前通过的云端 ASR/TTS 主机测试不等同麦克风/扬声器验收。修复包需重新烧录后确认 mediad 常驻、NTP、麦克风采样与发声；不能宣称已实机修好录音。
