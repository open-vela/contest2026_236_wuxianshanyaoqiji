# 绮迹：4 分钟现场演示与验收

## 实机演示安排

| 时间 | 展示内容 | 必须取得的真实证据 |
| --- | --- | --- |
| 0:00–0:25 | 使用场景、开发板、原创角色 | 镜头拍摄实体设备 |
| 0:25–0:50 | 当前版本、联网与服务就绪 | 构建时间正确；Wi-Fi 实际在线 |
| 0:50–1:30 | 第一轮：请绮迹介绍自己 | 人声、识别文本、正式回复、真实外放 |
| 1:30–2:10 | 第二轮：接着上一句继续聊天 | 没有重启或剪掉失败过程 |
| 2:10–2:50 | 空闲 30 秒后再次说话 | 无明显卡顿；旧录音不混入 |
| 2:50–3:25 | 展示架构与原型工程难点 | 不把示意图当运行证据 |
| 3:25–4:00 | 开发成果、复用 Skill、当前局限 | 说明已验收与未验收部分 |

若某步没有通过，保留事实并缩小宣称范围。不要用电脑生成的音轨覆盖设备声音后称为板端外放。视频内容只展示必要配置，不拍 API Key。

## 放行条件

- 核对设备构建时间为当前候选版本，确认应用、媒体服务与 Wi-Fi 在线。
- 现场人工至少三轮语音交互，包含 30 秒空闲间隔。逐轮核对识别内容、角色回复和声音。
- `python tools/board_acceptance.py --exercise --rounds 3 --idle-seconds 30` 执行相同的按钮工作路径并保留 JSON；测试会实际录音和调用已配置的云端服务。
- `complete=true` 仅说明脚本完成检查；还要检查各轮 `software_dialogue_completed`。物理听感和识别准确率由人工确认。
- 再做一次冷启动，检查 Key 保留、Wi-Fi 和时钟；当前软件 reboot 曾进入 FEL，不作为正常重启方案。
- 在可恢复条件下短暂断网，记录界面和恢复过程；这项目前尚未通过，不能在视频中宣称已有可靠断网恢复。
